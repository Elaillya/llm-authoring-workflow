# 完整出题与五模型排序规则

规则依据：2026-10-12 保存的《【开放难题五期】评测集外发方案.md》和《试标验收问题汇总.md》，及用户本次指示；来源哈希见 source-manifest.json。本文件包含出题及排序规则，可独立使用。收到项目方原文的使用者可将其保留在个人工作区reference/，无需将原文发布到GitHub。

## 输入与题型

新题按begin菜单先询问计算机科学、商科或生活爱好类，再问子方向，最后选择三种题型之一；用户已明确的选择直接记录。CS分日常AI使用与学习、大学课程、科研和生产开发；商科七分支与参考机制卡相连；生活爱好采用多层主题与横向情境标签，按docs/LIFESTYLE_CATALOG.md选择范围，可明确停在内部节点。场景、事实和限制由助手按所选范围生成核实，不虚构个人经历。

候选自然表达和跨题差异的单一规则见natural-diverse.md；本地题库使用及复核见../docs/LOCAL_MEMORY.md。设计前读全库机制索引，比较题面、Insight与考点评分结构，助手完成复核和预留后冻结；不用额外用户审批。商科从business-reference.json查适用原始资料，逐题核验条件与事实。生活爱好按docs/LIFESTYLE_REFERENCES.md选匹配机制和已读来源，缺口由助手查证并补充本题资料，不复制情境种子。旧冻结题沿用原领域，不强迫改题。

题面不超过100字符，语言自然、方向明确，必要条件完整。具有开放性和客观认知区分，不用冷僻陷阱和隐藏标准“考倒”模型；避开1–3个月即失效的热点、价格或短期现状。不要用堆词或简写掩盖关键条件。

分析决策类：必须做出明确决策；有给定候选时最终结论落在某个候选内，候选各有优劣。Insight解释核心变量如何改变取舍，不把已选方案的部署细节当成选它的理由。纯解释现象、罗列条件或以“还需确认”结束不满足。

开放推荐类：通过场景隐含需求推导筛选画像，再推荐有限候选；不是直接给齐A/B/C条件后检索，也不是很多答案都满足的空泛推荐。How-to类：问题明确询问可执行方案，步骤主线及先后顺序由Insight决定；避免简单界面/API操作，也避免把纯原因解释伪装成How-to。

## Insight、考点与作者自查

Insight以灵活的纯文本突出真正改变答案或行动主线的决定性因素，满足必要性、决定性、特异性、共识性。可以单段、因果解释、对比，也可按需分成机制、优先级与结论；不强制三段。解释该因素为什么关键，落到明确判断。形式变化不能掩盖一般背景或通用建议缺少决定性。写法与自查见Skill的references/writing.md。

考点以明确、具体、可判断的信息或推理要求描述。每条只判断一个核心事实、关系或行动，能够独立判定的要求拆开；减少题面已给的背景，保留影响判定的必要条件。Insight展示“为什么”；考点提炼“回复说明哪些内容才能满足”，两者不能简单复制粘贴。不能机械拆词或重复计数来改变排名。没有决定性点时无法成立；只满足辅助细节不代表答对。

非决定性核心考点可选。没有则 points 只列 decisive，最终字段写“无”；有则列 supporting 供五模型统一评估和排序使用。不要为了产生满足数量差异添加考点。

查看真实回复前记录并冻结候选题面、Insight与考点，这是候选版本记录；三模型验证和自查通过后锁定最终提交版。先筛查Turbo，全部达成则修订候选，不进入GPT/Claude验证；未达成再获取另两者。修改题面重新采集；修改考点统一重评全部三个模型。新启发必须重新论证专业必要性，不能从回答捡边角差异倒推评分。保留旧版本和负结果。

对照验收反馈完成作者自查，按当前题型补充专属检查。新任务按Skill的references/platform-checks.md执行主流程内的三项平台检查；合理问题自主返修复检，错误意见保留原不通过并登记证据异议、告知用户及填表备注。甲方最终验收仍由甲方执行。

## 三模型验证与完整性

模型固定为 Seed 2.1 Turbo、GPT-5.6 sol、Claude Opus 4.6，后两者使用中高推理。用户在对应型号的官方页面新会话获取原文，填入工具创建的 Markdown 文件。不使用 API 配置，不自动调用，不渲染网页或回答截图。所有官方页面截图由用户单独提交甲方。

先冻结候选，再创建 Seed 文件。导入并完成当前版本决定性考点判断后，只有 Seed 未全部达成才创建 GPT/Claude 文件。五模型发送内容严格等于冻结prompt，不追加格式指令或其他前后缀，不带Insight/考点；保存完整原始字节，原有代码块保留，不改写或补写截断内容。网页无法确认规定型号时记为缺材料，不使用相近版本。手动 Markdown 的来源为用户声明，不代表工具独立核验网页、型号和模式。

逐项判断全部决定性点：满足/不满足、具体原因、原文证据。所有决定性点都满足才整体达成；猜对结论但缺决定性理由仍不达成。三模型出题门槛只评决定性点；五模型排序另补所有模型的非决定性点判断。

区分度门槛：Seed未达成全部决定性点，且GPT或Claude至少一个达成全部决定性点。在该门槛通过之前不调用考点质检或达成性质检；GPT和Claude都未达成时保留失败候选、按题库记rejected并重新选题生成新prompt。三个完整回复都必须保存；未得到完整回复、身份不符、网络失败或专业前提不明时，记证据不足，不记为考点失败。

验收反馈建议回复过短时重新生成。先检查是否截断、格式或服务问题；确有必要时记录原因并保留各次原件，不因“效果不好”挑选有利样本或持续收费重试。如确需再次获取，说明具体原因并保留旧原文；多次成功样本需要在新候选目录保留和说明选择，不覆盖旧成功样本。

## Arena与五模型排序（2026-10-13用户更新）

新流程在prompt/Insight后先通过难度标签检查；三模型及判断齐备后先通过原有三模型门槛，再进行考点质检和达成性质检（或登记有证据异议），最后进入Arena与排序。不合格候选直接保留负结果并转向新prompt。仍不拆上下轮或另开专家质检流程。登录/网络错误不能豁免，模型原文不改写，修改后的输入重检。

Arena按项目规定使用Search联网、Battle Mode、新会话，偏好选择后记录真实型号；两个模型不得相同、不得与前三个相同、不得为GPT/Claude系列。工具创建两份Markdown填写文件，用户只填型号和完整原回复，截图自行交给甲方。输入绑定冻结题面，按用户提供来源记录，不冒称工具核验了页面或随机性。

五模型决定性达成性仍要求全部决定性点。排序额外逐项判断全部非决定性点，不改变原冻结标准。已有三模型决定性判断复制到新增五模型评估；辅助点未评不能视为未满足。

排序按两梯队：全部决定性达成优于未全部达成，同梯队按全部考点满足数排序，同数并列。结果和理由直接使用真实模型名称，固定展示顺序Seed/GPT/Claude/两个Arena型号。纯文本简述具体考点达成差异及原因，覆盖五模型并突出影响次序或并列的关键区别，不重复长篇引用、不设字数下限。不能引入文风、品牌、长度或隐藏考点打破同分。

完整交付保留六个文件：提交信息.md用纯文本字段和段落呈现题目、Insight、两类考点、各模型达成性/备注及决定性核心考点的达成性排序说明；五份原回复单独按模型名保存到models/。原文保持原始Markdown字节，主文件给出回复路径，不内嵌回复全文。输入原件、来源证据、作者自查及manifest保留为辅助记录。全部官方网页图由用户单独提交。旧交付不覆盖，新版本写新目录；不生成交付ZIP。软件生成材料不代表甲方验收通过。
