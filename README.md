# LLM Authoring Workflow

开放难题第五期完整出题与五模型排序工具，适用于Codex侧栏。选择领域/子方向与题型 → 读题库和资料 → 生成自然prompt与Insight → 平台难度与标签检查、修订复检 → 完成考点、多样性复核和冻结 → 用户提供Seed，符合筛查条件再收GPT/Claude → 三模型判断及考点/达成性质检、返修或证据异议 → 门禁通过后Arena → 五模型排序 → 六份Markdown交付。

前三个模型固定为 Seed 2.1 Turbo、GPT-5.6 sol、Claude Opus 4.6。非决定性核心考点可选，没有时输出“无”。**不调用模型 API，不要求配置密钥，不生成截图。所有官方网页截图由用户另行提交甲方。**

## 第一次使用

1. Clone 本仓库，在 VS Code 打开仓库，在 Codex 侧栏发送：

   ```text
   按 AGENTS.md 为我创建独立工作区并开始完整出题流程。
   ```

2. 助手准备依赖和独立工作区。打开生成的 `Authoring.code-workspace`。本项目共用的质检配置已随仓库提供；首次需要质检时，助手给你已创建的 Cookie 文件链接，填入自己的登录态即可，无需提供 HAR 或另找 service.json。
3. 先选计算机科学或商科，再选对应子方向，最后从分析决策类、开放推荐类、How-to类中选一种。问题、事实、限制、资料核实及跨题查重由助手完成；materials/可以为空。

手动准备也可以：

```bash
python3 scripts/setup.py
.venv/bin/python scripts/lab.py workspace-create ../my-authoring-workspace
```

环境要求 Python≥3.10、Git、Linux/macOS；Windows 使用 WSL。默认只准备 Python 依赖，不下载浏览器和中文字体。

## 选题范围与本地记忆

计算机科学有四类：日常AI使用和学习问题、大学CS课程与实验、研究生科研、真实生产开发。日常题贴近生活，课程/科研/生产题按受众保留必要专业性，避免术语堆砌或为了出题而造难题。

商科有七类：日常小微经营、营销/用户/定价、运营/供应链、管理会计/经营财务、组织/激励、商业分析/实验、战略/商业模式。参考库含已核验的一手来源与机制卡，详见[商科资料说明](docs/BUSINESS_REFERENCES.md)；每道题仍需核实原始资料、设定和适用边界。

父工作区local/question-memory.sqlite3保存题面、Insight、考点及设计画像，跨题目和窗口共享。助手读全库机制索引、进行文本召回与语义复核，避免仅换名称、数字和句式。完全重复会阻止冻结；近似项需要实质区别依据或重新选题。详细接口与能力边界见[本地题库说明](docs/LOCAL_MEMORY.md)。这份私人记忆不进入GitHub，也不写入全局Codex记忆。

## 怎样提供五个模型的回答

冻结候选后，助手先创建 `model-input/rNNNN/prompt.md` 和 `model-input/rNNNN/Seed 2.1 Turbo.md`，并给你可点击链接。

复制 `prompt.md` 到对应型号的官方网页新会话；将完整回答的 Markdown 原文粘贴到 Seed 文件里，替换占位文字，保存后在侧栏说“Seed 已填好，继续”。不用自己创建文件，不用加任何标题、来源字段或外层代码块；不改写或补写模型回答。

助手导入并按冻结的决定性考点判断。**Seed 未达成全部决定性考点时，才创建 `GPT-5.6 sol.md` 和 `Claude Opus 4.6.md`。**这两个型号按项目要求使用中高推理模式，发送相同题面和格式指令，填好后说“GPT 和 Claude 已填好，继续”。如果官方页面不能确认规定型号，说明缺少该型号，不能用相近版本代替。

Seed 若全部达成，助手保留该结果，重新论证并修订候选；新题面重新取 Seed 回复。已有完整原件不覆盖、不重新索取；只修改 Insight 或考点时，对相同题面的原回复统一重评，不按现有回答倒推标准。

三模型门槛为Seed未全部达成、GPT或Claude至少一个全部达成，三份原文均须保存。还需完成平台考点和达成性质检，合理问题助手自主修订；可核对的错误意见保留原不通过、登记证据异议并向用户解释和提供备注。门禁满足后才创建Arena的两份模型MD和题面，填入Search + Battle随机两模型。型号不得重复、不得与前三个相同、不得为GPT/Claude系列。

## 平台三项检查

平台质检服务允许自动调用，与自动生成模型回复的API分开。prompt与Insight形成后先做题目难度/标签判断；三模型原文、达成判断及备注齐备后，用`qa-run models --evaluation <当前三模型评估>`并行做考点与达成性质检。正常请求等待到完成，不设客户端时间上限。合理不通过由助手返修复检；登录或服务错误保留并处理，不重复发送结果未知的请求。

三项实际通过且三模型门槛满足后，先给你Arena的填写链接，再处理通过结果中的表达建议。优化不改变正在收集的题面、专业含义、模型原文或达成标准；改写另存记录，最终提交使用优化表达并注明优化后未复检，不再调用质检。实质改题建议保留给后续候选。

仓库自带[共用项目配置](config/aidp-service.json)，包含本项目任务与三个检查计划ID，不含Cookie、原题itemID或会话参数。缺少本地service.json时，首次读取质检配置会自动复制它，并创建父工作区local/aidp/cookie.txt；你只需在需要时填写自己的Cookie，过期后更新同一文件。已有私有配置及Cookie不会被替换，其他平台任务仍可用`qa-setup --config <文件>`或`--har <文件>`导入。

已在使用旧版的同学可以先下载共用配置，在Codex侧栏说：“导入这个aidp-service.json作为平台质检配置，保留已有题目，然后给我Cookie填写文件的链接。”助手运行`bin/lab qa-setup --config <该文件的绝对路径>`即可。更新仓库后也可直接运行`bin/lab qa-setup --default`，不需要HAR。

平台任务ID对应整个任务，itemID对应网页中的一道题；当前调用没有单独的itemID参数。公开配置使用站点根地址作Referer，去除了旧题地址；这份净化Referer尚未做线上调用验证。只有质检请求会发送到固定AIDP站点，不调用网页暂存或提交。细节见[共用配置说明](docs/SHARED_PLATFORM_CONFIG.md)。

不认同有证据可核对的错误质检时，助手保留原返回，明确告诉用户“不认同该不通过结论”，生成可复制表单备注；本地状态记为有证据异议继续，不冒充服务通过。细节、命令及表单放置方式见[平台检查与返修](skills/llm-authoring-workflow/references/platform-checks.md)。旧任务继续原合同，不因更新自动清空或重做。

工作区对五份 Markdown 做完整性、版本绑定和逐点判断；用户提供的来源声明不等于工具已核验网页、型号、会话或随机过程。全部官方网页截图由你另行提交。

## 交付内容

最终交付六份方便复制的 Markdown：

- `delivery/vNNN/提交信息.md`：题目、题型、Insight、两类考点、五模型达成性及备注、具名排序和排序理由。
- `delivery/vNNN/models/`：五份按真实模型名命名的原回答，不在提交信息中重复内嵌。

没有非决定性核心考点时填写“无”。排序先比较全部决定性考点达成性，再在同一梯队按全部核心考点满足数比较，相同并列；排序和理由直接使用模型名称，理由至少 500 字。证据不足不能记为未达成。JSON、原始输入及哈希清单保留作记录，不生成交付 ZIP。

## 每道题打开一个窗口

在侧栏说“新建题目 <题目编号>”，把 `<题目编号>` 换成你希望使用的编号。助手运行 `bin/lab new <题目编号>`，创建 `tasks/<题目编号>/<题目编号>.code-workspace`，用新窗口打开即可。各题有独立 Git、题面、回复、判断和交付，共用运行环境；每道新题分别选择领域和题型。

已有题目可以运行 `bin/lab rename <新题目编号>` 改名，保留冻结 ID、证据、Git 历史和旧路径入口。

## 更新和接续

在工具仓执行 `git pull --ff-only`，再由侧栏运行 `scripts/lab.py --workspace <已有工作区> workspace-update` 更新说明。该命令保留既有题目、原文、判断和交付，不自动清空题目。

3.0.0 起默认手动提供所有回复；`collect`、`recover`、`render` 入口停止执行。旧 API 原件与截图可作为历史材料继续读取和导出，历史 API 渲染图不能充当新要求的官方网页截图。旧私有配置不会删除，新题不读取或要求配置它。

侧栏开始指令：

```text
按AGENTS.md开始或接续完整出题流程。先选领域、子方向、题型，读题库和资料，prompt与Insight先做平台检查再冻结。模型回复手动Markdown，先Seed再按门槛收GPT/Claude；三模型原文、判断及备注齐备后并行考点与达成性质检，正常请求等至完成。合理不通过返修，有证据的错误意见立即告知不认同并给可复制备注。门禁满足后先发Arena填写链接，再离线优化三项实际通过的表达建议，优化后不再质检。缺失/过期Cookie给已创建的私有文件填写。模型生成API不调用，平台检查允许调用，截图我另交。
```
