# 3.2.1 三模型门槛先于后两项质检

用户2026-10-15明确要求：GPT和Claude都未达成时，当前prompt不合格，保留失败记录并转向新prompt；不调用考点质检或达成性质检。

- 唯一允许发送后两项质检的条件：同版三份回复、逐点判断和备注完整有效，Seed未全部达成决定性核心考点，且GPT或Claude至少一个全部达成。其余情况均在本地拦截。
- 统一防护覆盖qa-run models、criteria、attainment及--refresh，位于配置/Cookie读取、历史缓存读取、意图落盘和网络调用之前。旧通过缓存不能绕过当前门槛。
- status/qa-status能识别完整但不合格的判断，显示candidate_rejected并提示保留负结果、重新选题；不能把失败判断当缺少评估、继续引导质检或Arena。
- 领域/题型及其他流程不变。prompt/Insight阶段的题目难度标签检查仍正常执行；合格三模型后仍并行两项质检、复用有效缓存、正常等待至完成。
- 失败候选由助手按现有本地题库流程标记rejected，保留题面、原回复、判断和已发生检查记录，生成真正不同的新prompt再走题目检查和Seed优先采集；不能仅为命中而放宽考点或改判。
- 仅应用至新版父工作区及其任务；不清空正在做的题，不自动重发平台请求，不修改旧父工作区。正常发布至用户GitHub仓库，不包含私人题目或登录态。
