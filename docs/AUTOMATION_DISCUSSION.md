# Arena 前自动化分支需求讨论稿

状态：需求讨论完成；pi-web 与做题平台均已实站验证通过（2026-10-24，见下方验证结论）；实施规格待整理确认。尚未修改现有运行流程。

## 已确认范围

- **轻量化调整（2026-10-24）**：自动化分支只提供流程与规则指导，不新增强制的阶段检查与门禁。运行计数（候选预算、方向连败、重取、修复轮）由助手按指导自觉执行并记录于任务 WORKLOG.md；本地平台检查门禁通过任务创建参数 `--no-platform-checks` 关闭（现有代码内置开关），本地三模型门槛保留；三项质检照常在平台网页真实执行，约束来自平台自身"确认后继续"机制。pi-web 回复经标准填写与导入路径入库；2026-10-26 优化后会话级溯源由采集回执保存，WORKLOG 引用目录。实施按[轻量版规格](AUTOMATION_SPEC.md)执行。

- 在流程开头选择手动或自动化分支。保留原手动流程；题库记忆、实质避重与覆盖统计等通用优化可服务两个分支。
- 自动化分支由用户首次指定顶层大方向。同一会话后续出题沿用，直到用户明确更换。
- agent 查询当前题库，自主选择细分方向与题型，避免核心任务、机制和关键情境实质相同或高度相似，并尽量覆盖多个方向与题型。同一细分方向允许出实质不同的题目。
- 模型回复拟通过用户提供的可访问 pi-web 服务地址获取。项目地址：https://github.com/agegr/pi-web 。公开文档读取未成功，具体能力待实际网站验证。
- 每个候选、每个模型使用独立新答题会话，只接收冻结 prompt，不接触 Insight、考点、其他回答或出题工作区。具体隔离能力及隐藏系统提示、工具配置待核验。
- 自动化分支固定执行题目难度与标签、考点、达成性三项质检。使用浏览器在做题平台填写内容并启动检查，不调用质检 API。平台登录由用户完成。
- 各项质检在所需信息齐备且现有前置门槛成立后执行：题目检查在 prompt 与 Insight 形成后；后两项在三份原文、统一评估与备注齐备且三模型门槛成立后。
- 允许自动填写、暂存草稿与启动质检，禁止正式提交。
- 首版由用户提供一个可编辑的平台题目页面，不自行领取或切换平台题目；未来再讨论扩展。允许在该页面替换草稿处理后续候选，替换前本地保留已有内容、候选材料和检查结果；不得正式提交。
- pi-web 回复可作为自动化分支独立认可的来源，如实记录实际模型标识、模式、会话及原回复，不冒称官方网页采集。原手动分支保留官方网页来源要求；实际页面能力仍待核验。
- 质检存在可核对的错误或助手有依据的不认同时，保留原检查结论和输入绑定证据，填写异议备注后可继续后续流程，不将异议记成平台实际通过。平台技术上能否继续及备注位置待验证。
- 同题面允许重新获取 GPT/Claude 回复。触发条件仅限两种：首次 GPT 与 Claude 均未全部达成；或修正 Insight/考点并统一重评后三模型门槛不再成立。已有一个模型全部达成时不为更好回答重取；Seed 全部达成时更换新候选，不重抽 Seed。
- 重取上限：每个候选、每个模型最多额外获取 1 次完整回复，仅重取尚未全部达成的模型；Insight/考点修订不重置次数；prompt 改变视为新候选，计入候选总数。保留并归档全部旧原文及对应评估，不删除失败采样。
- 原文选择：每个模型以最新一次完整有效回复作为统一评估原文，新回复一旦有效不因表现更差回退；未完成或损坏内容不替换有效原文，也不计为完成一次重取；做题平台同步填写同一份原文。
- 有明确内容理由的质检不通过，按专业依据自动修订并复检，同一候选最多修复 2 轮；仍不合格则淘汰，计一次候选失败。
- 登录失效、验证码、型号不符、发送或检查结果未知时保存进度并暂停，不计候选失败，不重复发送结果未知的请求。
- 三模型门槛通过后，由 agent 用浏览器控制在 pi-web 中为三个模型的会话分别截图：问题、完整回答、使用模型与推理档位必须截全；截图完成后随质检材料上传做题平台。截图与上传不得改动会话内容，思考块保持折叠不入图。
- 自动化分支的平台操作止于三模型阶段材料齐备：内容填写、三项 AI 检查（含返修/异议/异常处理）、回复截图上传与暂存。“确认后继续”复选框、Arena 与最终排序区块不由自动化执行，由用户手动完成。考点质检与达成性判断仅要求正确读取结论与详情，具体内容分析由正式做题时的判断步骤进行。
- 首版得到一道满足 Arena 进入条件的题目后暂停。后续可扩展为积累用户指定数量的合格题。
- 候选总数上限可配置，默认 10 个。同一细分方向连续失败 5 个候选后切换细分方向；达到总上限保留所有原件并报告失败分布。
- 候选失败计数：同一候选的返修、修复轮与重取不重复计数，淘汰时计一次；登录、网络、服务故障及发送结果未知不计为候选失败。
- Seed 已知结果的技术失败（页面报错、回复为空、生成完但明显截断、格式损坏）同样允许自动重取一次：新会话获取，旧件归档，占用该候选 Seed 的重取额度；额度用尽仍无有效原文则暂停待确认。发送状态未知仍走暂停规则，不重发。
- 一次自动化运行对应一个题目任务：启动时确定题目编号，每个候选是该任务的一个冻结版本，失败候选记 rejected 后在同一任务内换新 prompt；大方向、剩余候选数、方向失败计数、重取与修复轮数、平台页面绑定等运行状态持久化在任务工作区，中断后从断点完整恢复，重启不重置计数。
- 选题覆盖采用软偏好，不设硬性上限：以整个共享题库中已交付或冻结题目（含历史成功题目，每任务取最终版本）的细分方向与题型分布为基数，优先选择覆盖较少的方向与题型；rejected 候选不进入分布统计，但全部参与实质避重。未配置共享组时统计当前父目录题库。

## pi-web 实站验证结论（2026-10-24）

环境：pi-web 0.12.2（pi 1.2.0），服务地址按本次实际部署确认；模型配置存于用户目录 `~/.pi/agent/settings.json`，经自定义 Provider 网关接入，已启用模型恰为三个目标型号。答题项目使用独立空目录，公开记录不保存个人机器路径。

- **模型切换**：会话内可在三个配置型号间切换（显示名 seed-2.1-turbo / gpt-5.6-sol / claude-opus-4-6），即时生效；新会话默认 gpt-5.6-sol。实测三家均成功回复。
- **推理级别**：会话可选 auto/low/medium/high。pi-web 支持设置新会话默认推理级别，用户已设为 high（实测新会话草稿默认 high）。自动化仍须在每次会话发送前检查推理级别，非 high 即切换为 high，并以会话记录中的 thinkingLevel 作为最终确认。实测 medium 与 high 均在会话记录中生效。
- **仅聊天隔离**：工具预设选“仅聊天”后无任何工具；系统消息为 pi 极简模板（编码助手人设、tools (none)、两条规则、pi 文档路径、cwd），不含出题资料；答题目录为空目录，无答案暴露。用户确认 pi 自带模板可接受。
- **会话独立性**：每候选每模型新建会话，互不干扰；侧栏支持置顶、重命名、分叉、归档、删除，会话可经 URL 恢复；页面重载后项目目录与“仅聊天”预设自动恢复。
- **回复导出（历史实测）**：会话以 JSONL 落盘于 `~/.pi/agent/sessions/<答题项目对应目录>/<时间戳>_<会话id>.jsonl`；assistant 消息 content 数组中 type=text 部分的 text 字段即完整原始 Markdown，thinking 块单独存放、提取时排除。页面另有人工“复制”按钮。当前采集主路径见piweb-http.md。
- **元数据与型号核验**：每条回复记录 api、provider、model（配置型号）、thinkingLevel、stopReason、usage、durationMs、responseId。按用户确认，型号核验以网页与会话记录中的配置型号为准；responseModel 字段仅参考记录，不作为阻断条件（实测网关返回名可能与配置名不一致）。
- **注意事项**：claude 经网关调用的输入 token 明显偏大（极短消息约 38k），疑似网关侧注入，来源条件按“pi-web 仅聊天 + 该网关”如实记录；生成期间出现引导/排队输入与停止按钮，完成判定以 JSONL 出现 assistant 消息及 stopReason 为准；发送后结果未知时不重发。
- **截图能力**：视口截图在内容较短时可单张截全问题、回答、回答上方的模型名与底部栏的型号/档位/预设；整页（fullPage）截图不含底部固定栏且实测出现重复渲染伪影，不采用；推理档位仅显示在底部固定栏（处理详情不含档位），因此长回答采用自顶向下滚动分段截图，每段视口截图均含底部栏，可在本地拼接后作为一张证据图上传。截图以 PNG 落盘于本会话工件目录，可归档进任务工作区。
- **已验证的自动化操作路径**：选择项目（重载后自动恢复，仍需核对）→ 新建会话 → 选模型 → 检查推理级别（非 high 切换为 high）→ 确认“仅聊天”预设 → 填入冻结 prompt → 发送 → 轮询会话 JSONL 至回复完成 → 提取 Markdown 与元数据归档；三模型门槛通过后重开各会话滚动分段截图。

验证期间产生的三个测试会话已由用户归档。

## 做题平台实站验证结论（2026-10-24）

入口路径：我的任务 → 任务详情（标注1-处理）→ mark-v3 做题页。页面为 Garfish 微前端 shadow DOM 应用，自动化需穿透 shadow root 操作。

- **表单字段**：题目类型（开放推荐/分析决策/How-to）、题目领域（法律/教育/计算机与数理科学/理工/人文社科/商科/医疗/生活娱乐）、题目Prompt（汉字上限100）、出题说明Insight、决定性/非决定性核心考点。
- **三个 AI 检查**（网页操作替代质检 API）：题目难度&标签辅助判断（五项子检查：领域一致性、题型一致性、难度阈值、汉字数量、通用基础质量；难度阈值通过线为难度系数 ≥6，用户确认，过简单时重新设计更高难度题目后重测）、考点质检、达成性判断。每项含运行按钮、异步结果（结论+详情，需等待渲染完成）、Agent 调用计数、Agent 结果正常/异常标记（调用报错或无结果时选异常可继续）、异议备注（0/1000字）和输入变更追踪（修改任一相关输入后需重跑）。难度检查实测返回"不通过+五项详情"，平台要求修改重测至通过，或填写不认同备注——与本地流程的返修/异议机制一一对应。
- **Seed 优先门槛由表单实现**：初始只有豆包 turbo 2.1 区块；其达成判断选"未达成"后，GPT-5.6-sol（中/Medium及以上推理）和 Claude opus 4.6（Medium及以上推理）区块自动出现。
- **模型区块**：Markdown 回复（校验要求包含标题/列表/引用/链接/表格/代码块等 Markdown 元素，粘贴真实模型原文即满足）、达成判断（达成/未达成二选一）、达成性备注、回复截图（每模型至少1张）。
- **"确认后继续"门槛**：三项 Agent 检查通过（或不认同备注/调用异常标记）后确认框才可用，之后才出现后续区块；Arena 与排序区块位于该门槛之后，本次未展开验证。
- **暂存**：字段变更自动提交暂存（SubmitTempItemAnswer）并更新"最近暂存时间"；页面重载后所有字段、判断和检查结果完整恢复。另有手动"暂存"按钮；"提交"未触碰。
- **截图上传**：向区块内 file input 写入 File 并派发 change 事件即可完成上传（file/upload → get_info → 自动暂存），字段状态变为"已完成"；内置浏览器的文件选择框不可用、拖拽弹层在 shadow DOM 内定位异常，均不采用，主世界脚本注入为可行路径。
- **自动化技术要点**：表单在 shadow DOM 内，Playwright 快照与定位可穿透；antd 下拉用真实点击或键盘（ArrowDown+Enter）选择；弹层可能定位到视口外，操作前先 scrollIntoView；evaluate 运行于隔离世界且带参数调用失效——写文件等操作需把数据写入 DOM 属性后注入主世界 script 执行。
- **测试残留**：验证过程向一个验证前为空的已领取题目写入了测试内容（生活娱乐分析决策题、豆包回复、未达成判断、一张测试截图）并已自动暂存；处理方式待用户确认（清空恢复或保留复用）。
- **范围确认**：考点质检与达成性判断的读取机制已由难度检查证实（同一异步结论+详情结构）；"确认后继续"、Arena 与排序区块不在自动化范围内，由用户手动完成。
- **操作配方**：全部已验证操作的逐步执行方法、定位方式、完成判据与陷阱规避见[自动化操作手册](../skills/llm-authoring-workflow/references/automation-playbook.md)（Skill references 目录，流程指导各阶段绑定必读）。

## 待验证事项

- 实站验证已全部通过；测试题目的测试数据由用户手动清空。
- 实施规格[轻量版](AUTOMATION_SPEC.md)已于 2026-10-24 按阶段 A–D、F 实施完成（新增 7 项合成测试通过、全量对照零新增失败）；首次真实自动化运行时按操作手册执行并回补经验。
- **首跑经验（2026-10-24，用户实测）**：流程正确性无问题。已回补一处判定规则：重跑质检的瞬间，结果区显示的是上一次调用的残留文案（"报错或未返回有效结果"），易被误读为本次调用异常；手册 §2.6 已明确进行中/完成/真实失败三态判据（按钮 loading=进行中；按钮恢复且结论更新=完成；仅完成态报错才选 Agent 结果"异常"），流程指导与陷阱清单同步。
- **性能优化轮（2026-10-25，已实施）**：用户反馈单题浏览器操作慢、额度消耗高；决议为混合路线（平台配方脚本 + pi-web 本地 HTTP、平台不复刻 HTTP、不设硬指标）。配方库七项（`references/automation-recipes/`）全部真实环境实测通过并接线为流程主路径，手册原步骤保留为回退；详见规格 §9。
- **长截图轮（2026-10-24，已实施）**：用户要求长回答合成单张长图。第一轮 clip 分段截取存在横向平铺伪影（像素级定位：984 宽合法截取，输出第 640 列起逐列重复开头 344 列，拼图呈"一图两页"），与 fullPage 伪影同族，clip 一并禁用；第二轮整视口分段截图 + 新配方 `stitch-screenshots.py` 校验裁边拼接，984×1023 单栏长图验证通过（正用例逐像素一致、负用例伪影拦截）。曾提出"临时调高视口（上限 3840×2160）一次成型"替代方案，超长回复仍需分段且用户选择维持多段拼接路线，未采用。详见规格 §10。

## 验证边界

平台"提交"从未点击；"确认后继续"复选框、Arena 与五模型排序始终由用户手动完成（设计边界，非未验证缺陷）。未调用按次付费的模型生成 API；模型回复采集走用户本地 pi-web 订阅。长截图在 pi-web 测试会话实测（合成测试回复，非正式题面）。
