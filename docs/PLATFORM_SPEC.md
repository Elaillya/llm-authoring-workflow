# 网页三项检查接入范围（2026-10-14）

基准c5b5ff8，仍是独立草稿，不更新现有工作区或GitHub。

1. 新建题目默认要求平台检查。大方向、子方向、题型与本地多样性流程保持。题面与Insight形成后先请求题目难度/标签检查；允许考点尚未完成。该项通过后才能冻结并收Seed。题面或Insight等真实请求字段变化使该通过失效。
2. 三个用户提供的原始Markdown与完整决定性判断/备注齐备后，用qa-run models并行考点和达成性质检；同一输入快照、独立落盘、保留部分成功。两项满足门禁且三模型门槛满足后才可准备/导入Arena和导出；旧版任务继续原合同。
3. 使用已观察到的AIDP接口及请求字段。Cookie只读父工作区私有文件，不打印/写入公开源码；缺失或401/403时给出已有填写文件。固定HTTPS站点，不跟随跳转，不调用暂存/提交。正常请求无客户端时间上限，旧配置数字timeout规范化为null，不自动重试未知状态。
4. 保存每次请求、返回、输入哈希和尝试状态；缓存只复用相同任务和当前请求绑定的已有结果。题目检查不依赖尚未形成的考点；后两项绑定冻结版本、三份原文与各自实际判断字段。上游修改使下游失效，旧结果和原件保留。
5. 对合理不通过由助手修订后再检查，不硬编码机械改写。题面变化重新收集；考点/Insight变化统一重评。侧栏指令要求自主执行这条循环，持续无进展、专业争议或网络错误时保存原因再报告，不无边界刷通过。
6. 对三项内容质检中可核对的错误意见，助手可记录异议，不新增用户审批。须绑定本次失败返回和输入，至少引用一条反馈及一条输入/原文，写实际理由及可复制表单备注，并立即告诉用户“不认同该不通过结论”。平台原始状态仍是不通过，本地状态为有证据异议继续，不能冒充服务通过。网络、登录、未知/缺少结果不能用异议绕过。
7. 异议和必要说明进入最终提交信息.md，保持六份交付Markdown；Cookie不进入交付。Arena准备、导入和最终导出均验证门禁，修改判断或原文不能借既有Arena文件绕过。状态命令不得把材料齐备误报成已通过平台检查。
8. 新增CLI用于私有配置准备、三项检查、状态、异议模板与登记；首次配置可从脱敏HAR提取元数据或导入既有私有配置，不能复制实际题目到通用源码。测试用合成数据/模拟传输覆盖版本绑定、过期登录、错误/冲突结果、异议证据和全流程，保留旧130项兼容验证。

2026-10-15补充：三项实际通过后先发Arena链接，再用qa-polish-template/qa-polish离线记录表达优化，无平台重检。冻结输入与原文不变，最终交付注明通过对应优化前版本。具体要求见QA_REFINEMENTS_SPEC.md。本轮仍只更新独立草稿，不部署、不推送。
