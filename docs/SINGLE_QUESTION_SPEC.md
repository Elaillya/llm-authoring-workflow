# 3.6.1 单一核心提问

用户反馈：有些题目把同一个任务写成多个问句或在结尾另问“为什么”，质检容易误判为多题。后续题面应只提出一个核心问题，把依据需求融入该问句，应用到v3工作区并推送公开仓库。

- 新候选先明确唯一决策或行动目标，再把必要约束、理由需求及相关安排收束为一个自然提问；需要解释原因时保留推理深度，通过“根据……”“怎样安排……才能……”等方式融入，不把“为什么/请说明理由”独立放在句尾。
- 多个子步骤可以服务于同一个目标，但不能把多个可独立回答的任务用逗号、分号或“并”硬拼。单个问号不等于单一问题；只有一个问号也必须语义复核。不同题目仍使用自然多样的表达，不套统一句式，不泄露Insight。
- 在题目难度/标签检查发送前，以及设计查重/冻结前，本地拦截明显多个问句和句尾独立追问原因。链接或行内代码中的问号不计为额外提问。代码检查只是显式写法检查，不代替语义判断。
- 设计复核新增single_core_question，助手写明唯一目标和为何相关内容属于同一任务；未填写或未通过不得冻结。先自查再发平台请求，不额外向用户加审批。
- 已冻结题面、发送文件、模型回复、评估、平台记录和交付保持；既有同prompt允许考点/Insight修复和续作，不因本次风格升级失效。以后更换prompt时按新规则检查、新建版本并从Seed重新采集，不能把旧回复绑定到改写题面。
- 仅部署v3父目录及其现有/未来任务；v2保留原工具。共享库、Cookie和私有配置不改，公开源码不含个人题面及回复。合成测试覆盖两个症状、正当单问、无网络拦截、缺复核和历史合同兼容。
