# 质检等待、并行与通过后优化（2026-10-15）

1. 三项平台质检不设客户端总等待或读取时间上限。旧私有配置中的数字 timeout_seconds 兼容读取，但规范化为 null，HTTP 明确传 timeout=None。请求正常等待到服务完成；身份认证、连接失败、远端错误等真实错误要保留并处理，不重复发送未知状态请求。侧栏使用可继续轮询的后台进程，每次短等并报告进度，不能因等待时间长中止质检。
2. 三份完整模型原文及逐点达成判断、引用、备注齐备后，qa-run models 同时运行考点质检和达成性质检。两项以同一输入快照准备，删除达成性质检对考点先通过的依赖；保留题目检查和三模型输入完整性要求。同题批次共用锁，分别立即保存返回；复用有效缓存，仅补缺失项。任一项登录/服务错误或未通过时，保留另一项结果；两项均满足门禁后才 Arena。记录未落盘或结果未知时不自动重发。
3. 三项实际结论均为通过且原三模型门槛满足，先创建并向用户发出 Arena 题面和两份 MD 填写链接，再处理通过反馈中的建议。优化为独立、可追溯的交付表达记录：允许改善 Insight、考点描述、出题说明、前三模型判断理由的表达；保持题面、专业含义、考点分类及达成标准、原文、逐点结论、引用和排序依据。每项改写须引用当前通过反馈及说明含义保持依据。实质改题建议保留为后续候选，不改正在收集的题面。本次表达优化不再次调用平台检查、不修改冻结证据；最终提交使用优化文字，并注明原通过对应检查时输入、优化后未复检，不假称平台已验证改写。改写不增加第七份交付 MD。
4. 不认同任何一项内容质检时，生成独立可复制的异议备注：明确“不认同该不通过结论”、具体理由、实际反馈与输入的准确引用、建议填写文字及放置位置，立即告知用户。允许三项真正的内容不通过按原有证据异议规则继续；身份认证/服务错误/未知结果不能豁免。保留平台原始不通过并显示 disputed，不冒充服务通过。仅有异议的结果不满足第3项“三项均通过”的条件。
5. 使用合成材料和模拟传输验证无限等待参数、并行重叠、缓存/部分失败/未知状态、原门禁、异议、Arena 通知后优化、交付字节与哈希。保留原159项回归；本轮不发送真实平台请求、不调用模型生成 API、不访问 Cookie。
