## 1. 目标与范围

推荐路径：用户确认服务地址及答题目录 → 原生 HTTP 核对模型与配置 → 独立会话发送冻结题面 → 轻量状态轮询 → 按会话读取并保存原回复 → 本地三模型判断 → 门槛后用 ego 批量分段截图 → 现有工具拼接和核验 → 现有平台上传流程。

以减少浏览器往返、避免误判完成及降低维护成本为目标。复用 pi-web 现有接口、ego 标准 API、现有拼接工具与 lab 导入命令。只做轻量采集和截图辅助模块，不新增工作流调度系统、命令族或专业门禁，不修改 pi-web 上游源码。

适用范围是自动化分支的前三模型采集及证据截图。Seed 优先、三模型门槛、题面版本、原文保护、回复替换授权、后续质检策略与 Arena 交接继续按本题已有合同执行；本计划不扩大重取权限。手动分支保持原要求。采集经用户 pi-web 服务进行，不另接模型厂商生成 API。

## 3. 目标操作规则

### 3.1 启动与模型配置

1. 采用 [automation.md 的启动步骤](../skills/llm-authoring-workflow/references/automation.md)，取得用户确认的服务地址与服务端答题目录；同题已有确认直接沿用。地址作为必填参数，支持已确认的路径前缀，拼接 API 与会话 URL 时不得丢失前缀。
2. 只读检查服务、模型目录与本机依赖。`GET /api/models?cwd=...` 核对本题规定的界面显示型号、provider 和 high 支持情况；每次运行预检一次，配置变动或异常后重新核对，避免每个动作重复读取。
3. provider 按当前服务的目录解析，不把 `ap`、`gpt` 当所有用户的固定配置。界面显示型号缺失或出现多个无法确定的 provider 时说明差异并确认，不用相近型号代替。
4. 认证信息只从本地私有配置读取，日志不输出密码、Cookie 或授权头。记录服务与浏览器版本；接口形状变化时先诊断，不自动升级或另起服务。

完成判据：地址、答题目录、三角色界面显示型号及 high 能力明确，必需运行时可用；尚未发送问题。

### 3.2 创建、发送与中断恢复

目标方案采用两段式：先 `POST /api/agent/new`，`type=ensure_session`，显式指定 provider、modelId、thinkingLevel=high、toolNames=[]；保存返回的 sessionId，核对实际配置后，再向 `POST /api/agent/<id>` 发送一次冻结 prompt。这样在生成前已有会话 ID，便于关联原文和处理中断。[接口依据](https://github.com/agegr/pi-web/blob/v0.12.2/app/api/agent/new/route.ts)

P2 阶段先验证 ensure_session 的生命周期、配置保持与发送语义，验证通过后才替换旧单次 POST；在此之前旧发送路径仍是现行路径。若两段式不适配当前版本，保留旧路径并记录原因，不在一次发送结果未知时切换路径重发。

每角色使用独立新会话。先 Seed，后续角色按本题门槛及策略启动，满足条件时 GPT/Claude 两个请求可并行。题面从冻结文件读入，发送字符串不附加前后缀、换行或格式要求；保存题面原件哈希及实际请求消息摘要。

发送前写私有调用记录：题目版本、角色、模型配置、sessionId（已获得时）、题面哈希、开始时间及待发送阶段；返回后追加受理结果。记录不是服务端幂等机制：本地没有回执不证明没发出，sessionId 已知也不能让 prompt 重复提交变得安全。

响应丢失、连接断开或客户端超时后，只读取原会话与运行状态，核对题面对应的用户消息及后续回复。不能凭运行列表中没有该 ID 就认定未发送；无法确认时保留断点并暂停该角色。HTTP 状态码或错误文案只能作证据，不能单独授权自动重发。已知失败的补取继续遵守本题已有规则。

完成判据：发送结果和会话关联明确，或已记录未知状态并停止进一步发送；没有隐式生成重试。

### 3.3 等待、读取与原文归档

采用 `GET /api/agent/running` 的轻量轮询，覆盖本轮相关会话；轮询在脚本内进行，只向助手输出状态变化、需要处理的问题及最终结果。观察窗口建议 15–30 秒，正常生成不设总时限；单次 HTTP 读取失败只重试读取，不重发 prompt。

不要把 `/api/agent/<id>` 或 `/api/sessions/<id>/state` 外层的 `running` 当成“正在生成”：0.12.2 源码中它可表示运行时仍存活。结合实际生成/重试/待输入状态与消息记录判定，具体字段和事件语义在 P2 验证。首版不引入 SSE 常驻连接；仅当轮询不能可靠判断重试等状态时，再评估原生 SSE，仍以会话落盘内容核验结果。[状态接口依据](https://github.com/agegr/pi-web/blob/v0.12.2/app/api/agent/%5Bid%5D/route.ts)

通过 `GET /api/sessions/<id>` 取得配置、消息 entry IDs、当前分支、正文及 filePath。将目标用户消息与冻结题面核对，选择同一回合当前分支的最终有效 assistant 消息；逐块按原顺序提取 type=text，不混入 thinking、工具内容、旧回合或错误尝试。[会话接口依据](https://github.com/agegr/pi-web/blob/v0.12.2/app/api/sessions/%5Bid%5D/route.ts)

| 观察结果 | 处理要求 |
|---|---|
| 正在生成、内部重试或待处理输入 | 等原会话；待用户输入时报告具体原因，不把已有 error 当终局 |
| 本回合结束，最终有效消息为正常 stop，正文完整且非空 | 核对配置及题面后归档；其他合法成功结束值须按实际版本明确验证后加入 |
| error、aborted、length、空正文或意外 toolUse | 分别记录报错、取消、截断、空结果或配置异常；确认没有后续生成/重试后才认定技术失败 |
| 运行列表消失，但无匹配的有效终局消息 | 保持未知，继续读取或保存断点；不自动新建会话 |
| error 后有最终正常回复 | 保留失败记录，导出最终成功正文，不拼接失败片段 |
| 多个候选回复、分支或题面对应不清 | 保留原件，暂停自动导入，不按“最新一条”猜测 |

保存 API 原始响应、选中 entry ID、最终 Markdown、正文哈希及来源元数据；字段缺失如实记录，不补造。JSONL 可读时使用接口返回的 filePath 对照，避免手工推导转义目录；服务在远端或路径不可读时归档 API 原件并注明未做 JSONL 对照，不把服务端路径强行映射到本机。正文保持原字符和换行，不 trim、不重新排版、不补标题，不进行网页复制往返。

继续使用现有 `model-prepare` / `model-import` 导入路径。已有有效回复不覆盖；题面未变时复用原文。新采集记录附着于既有任务私有记录，不改原件校验和专业评估机制。

完成判据：正文对应正确题面、角色、会话、回合和分支，结束原因已分类，原文归档可校验，现有导入成功。

### 3.4 长截图

仅在本地三模型门槛满足后，对已绑定会话的真实聊天页截图。主路径保持整视口分段采集与现有拼接器，在一次 ego 脚本调用中完成连续采集；超过单轮可承受范围时按段保存断点，不重新获取模型回复。

1. 复用同一授权空间和页面，打开实际服务地址下的会话链接；核对题面、最终回复、型号与 high。确认当前展示分支与已归档 entry ID 对应，错误尝试/思考块按页面正常折叠控件收起，不能改写或替换消息 DOM。
2. 等正文、字体及异步图表布局稳定。测量真实消息滚动容器、视口、内容高度与截图像素比例；检查横向溢出的代码/表格及未加载历史，先保证内容可见再采集。
3. 处理非正文浮层：优先使用正常页面控件或等待自动隐藏。确需临时调整浮动回底按钮、滚动条等 UI 样式时，仅作用于已核实的非证据元素，保留原样式，并在 finally 中恢复；不隐藏失败说明、型号、档位或其他证据内容。无法可靠处理就保留原图并标待修。
4. 每段设置滚动位置后回读实际 scrollTop，等布局/绘制稳定再截图，记录实际覆盖区间。每段保留适量重叠，最后一段到真实最大滚动位置；内容高度或横向位置变化时重新测量并重截受影响段。控制台只输出进度与文件路径。
5. 复用 `stitch-screenshots.py`，保留内容坐标衔接与平铺检测，末段附真实型号/high 状态栏。明确 CSS 像素与输出像素比例及取整策略，覆盖 fractional geometry、DPR、首尾边界；不能用高度近似相等掩盖正文缺行。
6. 拼接器成功后检查整张图的首尾、接缝、正文、公式、代码、表格和型号/high；保存原始分段、几何计划及最终长图。失败只重做截图相关步骤，最终上传沿用平台标准文件接口。

完成判据：问题与最终完整回复、型号和 high 均可读；无缺段、重复正文、截字、横向伪影和覆盖正文的浮层；截图后页面状态恢复。拼接输出的 `ok` 和进程退出码均应可靠表示成败。

聊天页 fullPage、直接 clip、HTML 导出截图不进入本次主路径。clip 的额外评估不得阻塞上述主路径交付；未来通过更多复杂内容/DPR 用例后可单独替换截图底层，保持完成判据一致。

路径中的配方文件均位于 `skills/llm-authoring-workflow/references/` 下。模块参数直接接收实际地址、目录、角色配置或 page；不编辑通用源码中的 DATA，不引入新的第三方浏览器库。两模块分别负责采集与截图，调用函数不隐式串起整个工作流。

## 5. 测试与验收

### 自动化回归（合成材料，不调用模型）

- 地址缺失、路径前缀、尾斜杠、不同 provider 同型号、高档位不支持、认证失败及接口变更。
- 中文/CRLF/前后空白/代码块题面发送不变，回复保留 Markdown 和换行；运行参数、日志中不泄漏认证信息。
- 单回合成功；error 后 stop；有正文的 error；截断、取消、空结果；缺失结束原因；内部重试、待输入；分支和多回合；响应或会话读取暂时失败。
- 创建成功但回执丢失、发送已受理但回执丢失、进程在记录前后退出；验证恢复只读，不把未知请求当成可重发。
- 已有有效原件幂等续接；版本、题面、角色不一致时不覆盖或导入。
- 截图首尾、重叠、覆盖缺口、分段尺寸变化、DPR 与小数坐标、横向溢出、内容高度变化、平铺伪影及浮层恢复；失败返回能让调用方明确停止上传。

使用 Node 内置测试验证轻量模块，纳入现有测试发现；Python 拼接测试使用合成图。实施代码后运行 `python -m unittest discover -s tests`；先核对仓库指定环境与依赖。无法在标准环境完成全量时，分别报告新增测试及与同环境修改前基线的差异，不声称全量通过。

### 实站验证

优先复用已有会话验证读取、原文对照、重试历史、长图和会话恢复，不为测截图重新生成回答。P2 的实际发送可在用户后续授权的正常自动化出题中观察，或有明确授权的最小试运行中验证；不能把模拟服务通过写成真实发送验证完成。

记录端到端耗时，并拆分创建/受理、模型生成、轮询发现、读取、页面加载、截图、拼接；同时记录浏览器调用次数和失败恢复情况。模型生成耗时单独列出，不归因于浏览器优化；不用当前约 0.8 秒的局部样本制定硬性 SLA。

## 6. 切换、兼容与回退
