# 3.6.2 Insight与核心考点研究的阶段应用

用户要求将本地研究报告与写作检查单纳入workflow，在出题各阶段作为必要参考，尤其确定Insight与核心考点时；应用v3工作区并发布GitHub。

- 完整研究的通用公开版与检查单位于Skill的references/insight-rubric-study.md及insight-rubric-checklist.md，随新任务与升级复制，不依赖/srv私有研究目录。保留53条历史/34次实验统计、三组返修变化、归因局限和反馈处理边界，不发布原题面、原回复、任务身份或认证信息。
- AGENTS、Skill及各阶段入口必须明确阅读条件与完成依据。开始/恢复读两份资料；Insight送题目检查前、核心考点冻结前、模型评估、返修、Arena排序和交付分别应用相关检查条目。该参考与用户是否选择后两项API无关，不改选择策略或调用数量。
- begin.authoring_references与design-check.required_references给出工具仓实际路径与必读阶段；新设计复核新增insight_rubric_alignment，passed必须为true且reason有本题具体说明：目标—决定机制—考点的对应、公开最低证据/等价路径及必需/可选边界。结构校验不能证明语义正确，助手必须实际复核，不自动生成通过理由，不向用户增加审批。
- 字数、句数、动作词及固定结构不是过检保证。研究未找到可复现的高通过率模板；不把无法质检/空结果当通过，不机械照单接受反馈，不添加隐藏条件维持Seed失分。原子性允许完整因果关系，独立要求才分开。
- 新设计复核需要新项；旧冻结读取和相同内容freeze幂等保持，旧自查/模型评估不因为本次文档升级追溯失效。同prompt修改Insight/考点须新版本和统一重评，prompt改变重新采集，旧原件和回执保留。
- 仅更新v3父目录和任务的指引/Skill/版本绑定，保留私有配置、Cookie、共享题库、任务Git HEAD、候选、原文、评估、平台回执和交付；v2不升级。发布前运行合成测试、检查发布范围与认证账号，正常快进推送，不调用平台或模型。
