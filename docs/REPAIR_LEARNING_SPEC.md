# 3.4.0 失败修复顺序与共享经验

用户要求：认可考点质检不通过时先评估能否通过专业上合理的Insight/考点与统一达成性重评修复；若不能保持三模型门槛，先询问是否替换GPT或Claude回复，仍不可行才修改prompt。同时本地记忆模型区分度失败与认可的三项质检不通过原因，父工作区各题共享，降低重复失败。

- 保持prompt优先。修正需有独立专业依据，不以命中结果决定标准；每条考点独立，所有已有模型统一重评。新冻结版本保留旧版本和评估。同prompt原回复已有prompt级存储与原文绑定，可直接复用，不迁移伪造新采集时间。Insight变化先重做题目检查，考点/判断变化按输入依赖重做相应检查。
- 无法合理修复时，明确告诉用户剩余考点缺口，询问是否重新提供GPT和/或Claude完整官方网页Markdown；未获用户明确同意不准备或替换。替换必须是完全相同prompt、指定型号与符合要求的推理模式，记录用户授权、原因、旧新哈希和原回复归档，保留所有失败评估/质检/交付；新增回复不承诺命中。替换后统一重评，门槛不通过仍不调用后两项质检。用户拒绝、无法提供或替换仍失败时再修改prompt、从Seed开始。不自动无限抽取回复。
- 初次Seed全部达成或GPT/Claude都未达成时继续遵守三模型前置门槛，不调用后两项质检，先记失败并转向新prompt；上述替换分支用于认可后期质检后的修复，不自动扩展成所有失败的盲目抽样。
- 失败观察保存在父工作区local/question-memory.sqlite3的附加表，旧entries/event与复核快照合同保留。模型判断检查命令和平台实际内容不通过自动记观察；纯check_seed/check_three验证函数及status只读题目证据，旧缓存复用不重复记同一个事件。支持初期尚无points的题目检查失败。
- 三项平台内容不通过先待作者复核，认可时填具体原因、可复用改进、适用范围和原始证据；有争议/未确认意见与登录/网络/未知结果不变成可靠经验。自动记录只确认本次模型门槛失败，不臆造跨题原因或普遍规律。复核历史追加保留，可用新复核纠正，异议会撤出认可经验。
- memory-context/begin在设计前给共享可靠经验和待复核观察；同父目录各题都可见，其他父目录与Codex全局记忆不写；私人题面、原回复、Cookie和失败记录不上传公开仓库。仅发布通用工具和规则。
- 保持五模型手动MD、发送文字等于prompt、Seed优先、三模型门槛后并行质检、无健康请求等待上限、通过后Arena先通知再离线表达优化、纯文本作者字段与原回复字节。错误质检仍按证据异议流程告知并给备注。
- 新代码使用合成材料回归、两轴复核；部署仅新版父工作区工具和侧栏说明，不改当前题目、原回复、评估/质检/交付或共享Cookie配置。无真实模型和质检调用。
