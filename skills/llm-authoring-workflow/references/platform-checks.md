# 平台检查与返修循环

这是主流程内的三个服务检查，不是另开一轮专家质检。模型回复仍由用户填写Markdown；允许自动调用AIDP质检服务，不自动调用Seed/GPT/Claude生成回复的API。

## 第一次需要检查时

父工作区local/aidp/保存service.json和cookie.txt，权限分别600、目录700。同父目录的题目共享登录态。助手先用`qa-setup --har <脱敏HAR路径>`提取三个计划ID、平台任务ID及普通请求头；已有私有配置可`qa-setup --config <私有配置路径>`。只提取元数据，不把实际题目、模型原文或Cookie放入通用仓库。已有Cookie原件保留。

准备好配置和填写文件后，才在需要时请用户填cookie.txt，并给可点击链接，不让用户自己创建文件，不在聊天索取账号密码或Cookie值。当前会话已有配置/登录态时直接复用，不重复询问。401/403时给同一个文件让用户更新；保留失败记录并等待，不把登录失效当题目不合格。

## 题面与Insight之后

1. 确认领域、子方向、题型；根据资料和历史题库写自然prompt与Insight。此时考点可以尚未形成，禁止为填表硬加考点。
2. `qa-run question --question drafts/question.json`。命令读取私有Cookie，只调用题目难度与标签服务，返回原始建议及记录位置。
3. 明确通过：接续考点设计、多样性复核和冻结；不通过：核实实际问题，自主修订题面/Insight，再执行同一检查。合理修订后连续推进，不要求用户替助手修改。
4. 同一输入已有结果时命令复用，避免无意义重发；只有输入已修改或有明确复核理由才重新调用，确需同输入复核时显式`--refresh`。网络失败、结果缺失或持续无进展时保留原因并报告，不能无限重试或猜测通过。

同题检查与异议登记共用锁。若进程中断或服务已返回但落盘失败，存在intent而无result的同输入尝试会报“结果未知”，包括--refresh也不会自动重发。先核对该尝试、已保存原文和平台状态，保留恢复说明；不凭删除锁文件或没有本地结果就假定远端没执行。

题目检查只比较实际题面、领域、题型和Insight；补全考点不使这项失效。平台标签映射位于私有service.json。How-to与计算机标签已有实测；其他标签如返回不一致，由助手根据当前页面核实映射，不能擅改用户选定的题型。

## 三个模型齐备之后

1. 保留Seed优先流程；三个完整原文、当前冻结考点下的逐点判断、理由及原文引用齐备，再运行`qa-run criteria --evaluation evaluations/three-rNNNN.json`。
2. 考点检查通过后，运行`qa-run attainment --evaluation evaluations/three-rNNNN.json`。平台结果需要同时核对HTTP、业务状态及内层结论。HTTP200本身不算通过。
3. 对合理意见自主返修。修改prompt建立新版本并重新收集；只改Insight/考点时按新版本统一重评三份完整原文；改变判断或备注时重跑达成性质检。按依赖重检，保留失败版本。模型原文不改写，不能按现有模型答案倒推有利标准。
4. 如果质检结论有可核对的错误，走下面的异议分支。平台检查通过或有证据异议被记录，且原有三模型区分度门槛通过，才能进入Arena。`qa-status --evaluation <当前评估>`可查看状态；Arena准备、导入和导出仍会再次验证。

## 有证据的不认同

只处理实际返回“不通过”的考点/达成性内容检查；登录、服务失败、未知结果和旧版本不能豁免。先区分确有错误、信息不足、自己评分不清和合理反馈；不能把每个不通过都归为质检错。

1. `qa-disagreement-template attainment evaluations/qa-disagreement-rNNNN.json --evaluation <当前评估>`；考点检查用criteria。
2. 助手填写reviewer、reason、evidence及form_notes。至少一条feedback引用和一条input引用必须逐字来自该次质检反馈与输入；引用模型原文时，input.field使用该请求中的模型回复字段名。给出完整专业判断，引用片段本身不等于已证明质检有错。
3. `qa-disagree <异议JSON> --evaluation <当前评估>`登记。命令保留平台“不通过”，本地状态标为disputed，不伪造通过。无需另向用户索取同意，但必须立即明确告知“不认同该不通过结论”，给具体理由、准确依据及生成的表单备注.md链接。
4. 优先让用户将form_notes复制到平台的质检异议/返修说明栏。若只能放入模型达成性备注，助手应先更新该输入、重新检查并重新绑定异议，不能沿用改动前的结果。不要假设页面一定存在某个未核实的字段。

条件式写法示例：只有在本次请求确实将Claude Opus 4.6判为全部达成，且本次质检说明也逐点判达成、没有提出其他可定位差异时，可写“我不认同本次不通过结论：提交判断与质检展示的Claude达成判断一致，现有反馈未指出实际分歧。保留同版考点及逐点原文依据，请复核具体不一致项。”实际使用时补上真实考点、引文和必要限定，不机械套用。未展开的其他模型不能推断为已获认可。

## Arena与交付

`arena-prepare --evaluation <当前评估>`后才给用户两份Arena填写文件；导入使用`arena-import --evaluation <当前评估>`。异议说明及可复制备注进入最终提交信息.md；实际请求和反馈保留为内部JSON证据，不增加第七份交付Markdown，不带Cookie。最终仍是一份非回复提交信息和五份按真实模型名称命名的原回复。

旧任务保持原合同。以后应用新版说明不会自动清空旧题、改写原文或强迫已冻结旧任务重走平台检查；确需旧题采用新流程，应由用户明确要求并保留迁移记录。
