# 由用户选择后两项平台质检

**适用范围：手动分支。**自动化分支按[automation.md](automation.md)默认执行三项网页检查，不重复询问本页的 API 选择。同题已有明确选择仍优先，跳过如实标注；不能因切换分支覆盖历史选择。

题目难度与标签检查固定执行；只有考点质检、达成性质检可以一起选择跳过。本文在手动分支优先于旧版“三项固定”的接续说明。Seed未全部决定性达成后、创建GPT和Claude填写文件之前读取本文。已进入中途而尚无选择时，在继续这两项检查或进入Arena之前补问，不重收已有回复。

1. 读取begin/status的model_checks_policy。choice未定时，用request_user_input_async询问“是否进行考点质检和达成性质检？”，选项为“需要”和“不需要”。说明题目难度与标签检查、三模型达成性门槛保持。等待实际答复；预选、沉默或授权启用这个功能都不等于本题选择。等待时可整理已得Seed证据，先不创建GPT/Claude填写文件。
2. 助手按实际答复运行choose-model-checks required --user-note '<实际答复及上下文>'，或choose-model-checks skipped --user-note '<实际答复及上下文>'。命令为本题追加私有选择记录、绑定到TASK.json；当前题后续版本沿用，新题独立选择。用户以后明确要求改变时再记录新选择，历史不覆盖。无需用户另填配置文件。
3. 给出GPT/Claude两个已创建的填写入口，仍只接收官方网页完整Markdown，发送文字严格等于prompt。回复和判断齐备后先lab check并读取three_model_gate。两种选择都必须满足Seed未全部决定性达成，且GPT或Claude至少一个全部达成。门槛失败按既有流程记原因、修复或换新prompt，后两项API都不调用。
4. 选择required时，按platform-checks.md执行qa-run models并行检查，等待、缓存、服务错误、合理返修、证据异议与失败经验均沿原规则。选择skipped时，从主流程去掉这两个调用，直接确认有效题目检查和三模型门槛，再arena-prepare，给出两份Arena Markdown填写入口；不为了补齐历史503重试。工具对批量/单项/refresh统一返回skipped_by_user，且不读取后两项缓存或发送请求。
5. 跳过是用户选择，不能写成通过；旧不通过、503、异议和原模型回复不删除。交付保留题目检查实际证据，附本次选择依据，并标明后两项未执行。三项实际通过才适用原平台通过后的免复检表达优化；跳过不满足该条件，不能引用旧三通过优化记录来声称本次三项通过。继续原五模型评估、具名排序、六份MD交付。

choose-model-checks仅改变后两项策略，不改领域、题面、模型答案、评分或Cookie。题目检查或本地三模型门槛未过时，选择跳过不能使Arena/交付放行。无需为已交付旧版本重新做检查；要继续中途题目或导出新版本时按当前选择与证据处理。
