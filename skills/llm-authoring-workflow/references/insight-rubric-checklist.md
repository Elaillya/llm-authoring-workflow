# Insight 与核心考点写作检查单

用途：出题与返修前的专业自查。由真实返修案例和对照实验整理；目前没有验证出大概率通过现行考点API的固定模板。完整证据见[研究报告](insight-rubric-study.md)。

## 各阶段必读与完成依据

本表由助手执行，不向用户增加填表或审批。开始或恢复时先读[完整研究报告](insight-rubric-study.md)和本检查单；同一上下文已完整读过可直接应用，进入以下阶段时仍须核对相应条目。报告是专业质量参考，不是API通关模板。

| 阶段 | 必须考虑的内容 | 完成依据 |
|---|---|---|
| 选题与构造prompt | 一个现实核心目标，哪些事实真的影响选择，是否需要独立核实 | 来源/设定笔记能区分真实依据、构造条件与适用边界 |
| 确定或修改Insight，题目检查发送前 | 本报告的机制到决策、适用限制及反面例子；本单“写Insight时” | 写清决定因素怎样改变本题结论，不只贴高阶标签，不强制同一段落结构 |
| 确定或修改决定性/非决定性考点，设计复核与冻结前 | 本单“每条核心考点”和“对应检查”；报告三组修复及因果局限 | 在现有insight_rubric_alignment.reason中说明双向覆盖、最低证据/等价路径、必需/可选边界和反例检验；适用的失败经验落实到本题，缺项先修候选 |
| Seed、GPT/Claude及Arena达成判断 | 用同版公开条文、真实原文证据，区分漏写、反证与等价实现 | 不用其他模型或外部知识补目标回复，不为维持Seed失分临时收紧规则 |
| 质检返回与返修 | 本单“收到反馈时”及报告的反馈张力 | 将认可的问题落实到具体修改；异议给输入绑定证据；无法质检、服务错误、空结果分开，不能记作通过 |
| Arena排序与最终交付 | 目标覆盖、统一判定、可选建议不变成隐性标准 | 新标准统一重评已有全部原文并重排；仅作表达优化时保持含义，说明未复检 |

只读报告或本地自查不会代替题目难度检查、真实三模型门槛、用户选择的后两项检查或平台验收。研究中34次调用的授权不自动成为每道题无限重发的授权；请求结果未知时仍等待原进程，不能因措辞建议刷结果。

## 判断模型时

模型判断时同时找支持与反证：错误替代建议若直接破坏该点要求，核对后文是否明确撤回、限定或纠正，不能只摘正确句子抵消冲突；无关瑕疵不扣该点。区分受限基线、被否定的反例与实际推荐方案。在现有reason/quotes里简述冲突及处理依据，对五模型统一标准，不新增评分项。冻结前仍说明本题风险、替代路线和覆盖关系，不以“已全面检查”代替查漏。

## 写 Insight 时

- 我能否用自己的话说清：这道题最容易误判的地方是什么，哪个机制或约束真正改变选择？
- 是否写出了“题设条件怎样影响结论”，而非只有常识介绍、概念名称和注意事项？
- 最关键因素是否突出？可以开头点明、在推导后揭示，也可以用比较呈现，不强制所有题同一种结构。
- 是否把核心结论与适用边界讲清，没有把“可能”说成“必然”，或用未给出的事实填补论证？
- 是否删掉与这道题选择无关的背景，以及重复的评分话术？不要为显得高阶堆术语，也不要单纯追求最短。

## 写每条核心考点时

- 这条在判断一个事实、决策或因果关系吗？彼此可独立满足的设备、操作、限制等是否被不必要地捆在一起？
- 裁判能从回复中找到什么可见证据来判断？尽量少用没有边界的“合理、充分、兼顾”。
- 前提与结论构成同一关系时是否仍保持完整，避免拆成几个词汇命中项？
- 如果缺少这一点，答案还能正确完成核心任务吗？若能，它可能是非决定性增强或普通说明。
- 是否允许等价表达与真正完成目标的替代路线？例子是帮助理解，还是被误写成唯一设备/唯一措辞？
- 所有最低要求是否公开且源于题面实际需要？是否避免为制造某模型失分临时增加精度、品牌、分钟或术语门槛？

## 写完后作一次对应检查

冻结前在现有设计复核内完成以下检查；修订Insight或考点时也执行。重点是主动寻找缺项和误判，不能只解释现有考点为什么合理。

1. 先依据题面与已核实资料，独立推导完成核心任务的最小完整解题路线：目标、关键行动或推理、成立所需前提、失效条件及结论边界。再与Insight和考点比对，避免只围绕已写出的点自证；不从已收模型的命中情况反推标准。无需另写标准答案或新增文件。
2. 双向核对覆盖。从目标和必要前提出发，指出由哪些考点判断，或为何题设已保证、属于作者解释而无需另考；再逐条反查考点，说明缺少它会怎样影响核心任务。尤其查Insight已经提到、考点却遗漏的必要条件。配套建议有独立比较价值才设非决定性点，普通背景或豁免留在说明中。
3. 用两类反例检验边界。构造一个“所有决定性点都满足，但核心任务仍有实质错误”的简短答案轮廓，检查是否漏项；再尝试一条专业上正确的等价路线，检查会不会被现有条文误判。找到反例就修对应缺口或接受边界；找不到也说明实际检查了哪个风险、哪条替代路线，不只写“无遗漏”。
4. How-to题额外沿输入、执行、诊断与结果解释检查可操作性。声明成立条件，不等于已给出利用现有信息检查风险的方法；按本题需要区分必要行动、值得比较的增强及普通说明。不要求每题都有诊断点或非决定性点，也不限定唯一工具。
5. 将[失败经验复用](../../../docs/FAILURE_LEARNING.md)中适用的认可经验转换为本题的自查问题，核对具体条目；相似题材本身不代表适用。没有相关经验则按专业资料完成上述检查。

结果合并写入现有design-review的insight_rubric_alignment.reason：简要说明关键覆盖关系、最低证据与等价路径、决定性/可选边界、反例检验所得，以及相关经验实际避免了什么问题。无需另建清单、逐条抄写历史经验、增加审批或质检调用；这是agent的判断规则，不新增程序性门槛。已有冻结与原回复保持，仅在新候选或实际返修时应用。

例如，安全替代、便宜替代或易执行替代，并不自动等于完成题面目标；反向也不能把Insight中的每条背景和配套建议升级成决定性条件。

例如：

弱表述示意：充分考虑温湿度，提出合理配置。

较清楚的表述示意：结合题中两组温湿读数，判断罩内的叶气水汽压差高于敞放环境；计算或等价文字比较均可。

这在判断一个比较关系。设备组合、光照处理、无人运行若属于其他独立要求，分别判断。以上只是写法示例，不能当作所有题通用考点或已通过的新稿。

## 收到反馈时

1. 先读具体原文与当前输入，不只看“缺少 Insight”标签或90多分的评分。
2. 真漏核心目标、推理有误、判定边界含混：修到具体条目，保留旧稿，统一重评所有原回复。
3. 只是可选优化：决定是否值得采纳，避免把所有建议不断堆成新门槛。普通豁免可留作者判定说明，无非决定性点填“无”。
4. 不认可：保留平台结论，给出绑定该版本、该点和该回复的证据，不把 disputed 写成通过。
5. 无法质检、HTTP错误、空结果：分别记录。没有明确内容理由时，不编造某种写作错误。

三模型门槛不成立时先处理题目资格，不靠质检通过或文字润色代替；所有标准始终同等适用于 Seed、GPT、Claude。修改 prompt 需要重新采集回复。

## 返修备注的简洁写法

说明改了哪一处、解决什么具体问题、接受什么等价证据即可。例如：“将不额外加课的选择与允许原课内部微调的解释边界分开，D3仅判断是否因凑比例新增间歇；原课微调不自动判为违反D3。已按统一标准重评全部原文。”

这只是备注示意，不是已执行记录；实际未做完重评时不能照抄最后一句。
